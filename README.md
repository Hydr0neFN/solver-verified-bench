# solver-verified-bench

一組小型、可重現的題庫，用來比較 Antigravity CLI 能取用的模型。每題答案都由 solver 產生並確認唯一解，計分完全機械化。

> 英文版：[README.en.md](README.en.md)

**先讀這個：**[METHODOLOGY.md](METHODOLOGY.md) 說明這份測試*不能*用來主張什麼。最重要的一點是模型在測試中有程式執行權，所以分數是「模型 + 工具」，不是純推理。

## 重現

```bash
# 重新生成題目檔（固定 seed，與實際跑測用的逐位元相同）
python bench/make_tier1.py && python bench/make_tier2.py && python bench/make_tier3.py

# 跑單一模型；已有輸出的格子會自動跳過
bash bench/run-model.sh <model-slug> [parallelism] [tiers]

# 從原始輸出重新計分
python bench/score.py

# 檢查某道歸納題的規則是否真的唯一
python bench/audit_ambiguity.py
```

## 目錄

| | |
|---|---|
| `bench/` | 生成器、runner、計分器、歧義稽核 |
| `tasks/` | 實際送給模型的題目全文 |
| `truth/` | 答案，資料而非程式碼；含兩次改 key 的理由 |
| `results/` | 分數 JSON + 全部原始輸出、stderr、計時 |
| `METHODOLOGY.md` | 怎麼測的，以及不能主張什麼 |
| `ACCOUNT-PROVENANCE.md` | 哪些跑在哪個帳號，為何延遲不可跨組比 |

## 計分規則中值得注意的兩點

1. **模型跑爆自己的時間預算 → 計 0 分，不剔除。** 剔除逾時等於偏袒最慢的模型。而且逾時一旦發生就被釘死：事後重跑成功也不會把那一格改回來，否則「重跑到過為止」就能把真實失敗洗掉。

2. **基礎設施失敗（配額、節流、認證）則排除不計**，那不是模型的問題。兩者用 stderr 內容與耗時區分。
