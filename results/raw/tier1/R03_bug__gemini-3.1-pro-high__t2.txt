The code acquires locks by iterating over the `items` dictionary directly. Because different threads can request items in different orders (or dictionaries might have different insertion orders), threads can acquire locks in varying sequences. For example, Thread 1 might acquire lock A and wait for lock B, while Thread 2 acquires lock B and waits for lock A. This circular dependency causes a classic deadlock. To fix this, locks must always be acquired in a globally consistent order, such as by sorting the SKUs before acquiring them (`for sku in sorted(items):`).
